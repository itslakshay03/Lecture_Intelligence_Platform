# Final Limitations Audit — Phase 6

Consolidated, evidence-traced limitations across the entire study. Nothing here is hidden or softened relative to Phases 5/5.5's own disclosures.

1. **Small dataset (N=7).** Well short of the Phase 3-recommended N=18-20. Every quantitative result in this study is bounded by this sample size.
2. **Limited subject/domain diversity.** 4 subject domains (Operating Systems ×2, Computer Networks ×2, DBMS ×2, Artificial Intelligence ×1); 4 of LectraAI's own 6 lecture-type categories represented (COMPARISON, ARCHITECTURE, ALGORITHM, THEORY).
3. **Zero CODING or NUMERICAL category lectures** in the evaluated set — a real, disclosed gap; a real attempt to close it (Phase 5.5) did not succeed because the available tooling cannot reliably discover and verify new candidate YouTube videos (playlist pages are JavaScript-rendered and not scrapable with the fetch tool available in this environment).
4. **Zero human timestamp annotators** — RQ1's central evidence gap. Full annotation infrastructure (7 real lecture packages) exists and is unused.
5. **Zero human artifact reviewers** — RQ2's central evidence gap. Rubric and blinding protocol exist and are unused.
6. **Zero human claim-level groundedness labels** — RQ3's central evidence gap. A real, mechanical claim-segmentation (58 units) exists and is unclassified.
7. **Limited direct comparison depth.** Only 1 of 7 lectures has any Experiment B/C comparison data generated at all (real API quota constraints, §8 below, contributed to this scope decision).
8. **Model configuration limitations.** Temperature/sampling parameters are not pinned or programmatically recorded anywhere in the current codebase (`research/configs/model_configuration.md`) — an acknowledged, unresolved confound for any generation-to-generation comparison. The exact responding model (`gemini-3.6-flash`) was recorded per real call, but its sampling behavior is not otherwise controlled.
9. **Real API quota constraint discovered during execution:** a live HTTP 429 (`generativelanguage.googleapis.com`, free-tier daily quota of 20 requests/model) was encountered once during Experiment B generation; correctly handled by the existing fallback/retry logic, but this constrains how much further real-data collection is practical within a single day without a paid tier.
10. **Dataset discovery limitation.** The tooling available in this project (WebSearch, WebFetch) cannot reliably enumerate specific, verifiable candidate YouTube video IDs from a channel/playlist at scale — closing this gap in a future phase would need either a human-supplied URL list or an integrated YouTube Data API client (not present anywhere in this codebase).
11. **Extractive-summarization baseline excluded.** A real-transcript pilot (Phase 5) revealed that LectraAI's actual transcripts (spoken, comma-heavy, period-sparse) break the baseline's period-based sentence segmentation, collapsing the transcript into a handful of giant run-on "sentences" rather than real ones — a genuine format incompatibility discovered through real execution, not a toy-data artifact. Excluded rather than "fixed," since re-engineering it to look better would itself be a form of result manipulation.
12. **RQ3's automated groundedness proxy excluded.** Found, on manual inspection of real output, to systematically miscount markdown structural headers as factual claims and to miss simple orthographic variants via its exact-substring matching — a genuine construct-validity failure. Excluded rather than tuned, per the explicit instruction not to revive an unreliable proxy merely because it produces numbers.
13. **Test/production database co-mingling (pre-existing, not introduced by this research work).** Phase 1 established that the backend's automated test suite writes to the same SQLite database file as production; this research project's own real experiment executions similarly share that file, and this was accounted for by explicitly excluding all test-suite-originated rows from every reported statistic (Phase 5 §22).
14. **Single execution session for Experiment D.** All 7 real latency measurements were collected within one session/time window; network and API-load variability across different times of day or dates was not sampled, so the specific latency numbers should not be read as a stable, universal performance characterization.
15. **No OCR, no multimodal input, no user study exist anywhere in this project** — correctly absent (per Phase 1's audit), not silently assumed or claimed.
16. **No comparison with any commercial or third-party lecture-summarization system was attempted.** All comparisons in this study are internal (LectraAI's own deterministic path vs. an experiment-only direct-LLM alternative built specifically for this study).
